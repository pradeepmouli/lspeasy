# Design: `lsproxy` discovery & invocation polish

- **Date:** 2026-06-28
- **Status:** Approved (pending spec review)
- **Package(s):** `packages/core` (`@lspeasy/core`), `apps/cli` (`@lsproxy/cli`), `scripts/` (protocol codegen)

## Problem

`lsproxy --help <language> <namespace> <request>` shows Commander's flattened
args/options, but for methods whose params are deep JSON — `textDocument/codeAction`
(`range` + `context.diagnostics`/`only`), `completion`, `workspace/executeCommand`,
`workspace/applyEdit` — that's insufficient: the user is forced into
`call <method> --params <raw json>` blind. There's also no way to see a method's
**result** shape (needed to chain calls), and the drill-down help is plain,
uncolored Commander text. Discovery should be complete and agent-friendly, and
common methods should be invokable **without hand-writing JSON**.

## Goals

- Surface, per request: **params + result JSON Schema** (machine, in `--json`) and
  concrete **example input + example output JSON** (human, in text help).
- **Deepen `zodToCommander`** so nested-scalar / enum / scalar-array params become
  CLI flags — so common methods (codeAction) need no raw `--params`.
- **Color across all help surfaces**, including the `lsproxy config` commands.
- Single source of truth: derive everything from the existing Zod schemas
  (`getSchemaForMethod` + a new `getResultSchemaForMethod`) — no schema duplication.

## Non-goals

- Not making *every* param JSON-free: array-of-objects (`codeAction.context.diagnostics`),
  unions, and recursive `LSPAny` (`executeCommand.arguments`, `applyEdit`) keep the
  `--params` fallback; the generated example guides it.
- Examples are **synthetic** (schema-filled placeholders) — illustrate shape, not
  real data. No live-server capture in v1.
- No new top-level command surface — schemas/examples live in the existing
  `--help <lang> <ns> <req>` drill-down (`--json` for schemas, text for examples).

## Background (verified)

- Zod is `^4.4.3` → native `z.toJSONSchema()` (no extra dep).
- `protocol/schemas.ts` (auto-generated by `scripts/generate-protocol-types.ts` via
  `scripts/lib/metamodel-parser.ts`) has **159** `*ParamsSchema` + `LSPSchemas`
  (method→params) + `getSchemaForMethod`, but only **~9** result schemas. The
  metaModel request entries carry a `result` Type, so result schemas are
  generatable with the existing Type→Zod converter.
- `zodToCommander` already introspects the params Zod schema (shape, optional
  unwrap) to build CLI args — the input-example/flag-deepening work builds on that
  same introspection.

## Components

### 1. Result-schema codegen (`scripts/generate-protocol-types.ts`, `scripts/lib/metamodel-parser.ts`)
Extend the generator so that, for every request method, it emits a
`<Method>ResultSchema` (reusing the existing Type→Zod conversion on the metaModel
request's `result`), plus a `LSPResultSchemas` map (method→result schema) and
`getResultSchemaForMethod(method): z.ZodType | undefined` in `protocol/schemas.ts`.
Notification methods (no result) are omitted. Regenerate `schemas.ts`; the file
stays "DO NOT EDIT MANUALLY". (Implementation note: the codegen task begins by
reading the generator to confirm where request `result` Types are available and
how `*ParamsSchema` is currently emitted, then mirrors it for results.)

### 2. `exampleFromZod` walker (`@lspeasy/core`, new `example-from-zod.ts`)
Pure `exampleFromZod(schema: z.ZodType): unknown` producing a **required-only**,
typed-sample value:
- string→`"example"`, number→`1`, boolean→`false`, literal/enum→first value,
  object→required props recursively, array→one sample element, `{line,character}`→
  zeros, optional/nullable→omitted.
- **Recursion/depth guard** for recursive types (`LSPAny`): cap depth and emit a
  placeholder (`{}`/`null`) rather than infinite-loop.
Used for **both** input examples (params schema) and output examples (result
schema). Shares Zod-4 introspection idioms with `zodToCommander`; factor a small
shared helper (`unwrap`/`isZodObject`) into a core util if it removes duplication.

### 3. Deepen `zodToCommander` (`apps/cli/src/zod-to-commander.ts`)
Extend flag generation (Option-1 depth):
- Nested **scalar** fields → dotted flags (`--context.trigger-kind`).
- Enums / literal-unions → Commander `.choices(...)`.
- Scalar **arrays** → comma-separated (`--only quickfix,refactor`).
- Array-of-objects / unions / recursive `LSPAny` → unchanged `--params` fallback.
Motivating case `textDocument/codeAction`: `<file>` + `<range>` (existing
range pattern) + `--only` + `--context.trigger-kind`; `diagnostics` via `--params`
only if needed. Existing simple methods (file + position) are unaffected.

### 4. Surface in help / `--json` (`apps/cli/src/help.ts`)
- `--json` depth-2 (request): add `paramsSchema` (from `z.toJSONSchema(getSchemaForMethod(m))`)
  and `resultSchema` (from `getResultSchemaForMethod(m)`, omitted when absent),
  beside existing `arguments`/`options`.
- Text help depth-2: append colored **Example input:** (`exampleFromZod(params)`) and
  **Example output:** (`exampleFromZod(result)`, omitted when no result schema)
  JSON blocks, each labelled "(illustrative)".

### 5. Color across surfaces (`apps/cli/src/format.ts` usage)
Apply the existing formatter to `renderDrillDownText` (currently plain Commander
text — section headers, the new example blocks) **and** the `lsproxy config`
command output (`list`/`import`/`export`/`diff`), gated `isTTY && !NO_COLOR && !json`.
JSON output stays ANSI-free.

## Data flow

`getSchemaForMethod(m)` / `getResultSchemaForMethod(m)` → `z.toJSONSchema(...)`
(schemas, `--json`) and `exampleFromZod(...)` (examples, text). `zodToCommander`
consumes the params schema to build deepened flags. Color is a presentation layer
over the text renders.

## Error handling / edge cases

- Recursive `LSPAny`: `z.toJSONSchema` uses `$defs`/`$ref` (Zod 4); `exampleFromZod`
  depth-guards. If `z.toJSONSchema` throws on a pathological schema, catch and omit
  that schema field with a note rather than failing the command.
- Methods with no result schema (notifications, gaps) → omit `resultSchema` and the
  output example gracefully.
- Deepened flags must never regress existing simple methods or the `--params`
  fallback for complex ones.
- All `--json` output remains ANSI-free.

## Testing

- **codegen**: a sampled set of methods get a `*ResultSchema` + `getResultSchemaForMethod`
  returns it; notifications return undefined; `pnpm run build`/`type-check` stay green
  and the docs build passes (no raw `<...>` regressions).
- **exampleFromZod**: scalars, nested objects, enum→first, array→one element,
  required-only (optionals omitted), recursion guard; `codeAction` params → a
  sensible example.
- **zodToCommander deepening**: `codeAction` → expected flags (`--only`,
  `--context.trigger-kind`, `<range>`); array-of-objects still falls back; existing
  methods unchanged.
- **help.ts**: `--json` depth-2 carries `paramsSchema`+`resultSchema`; text help
  carries Example input/output blocks; no `\x1b` when color off.
- **color**: `renderDrillDownText` + config commands colored when enabled, plain
  when off; `--json` ANSI-free.

## Phasing (single spec, phased plan)

A. Result-schema codegen (core/scripts) — foundational.
B. `exampleFromZod` walker (core).
C. `zodToCommander` deepening (cli).
D. Help/`--json` surfacing of schemas + examples (cli).
E. Color across drill-down help + config commands (cli).
